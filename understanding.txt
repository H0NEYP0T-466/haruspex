HARUSPEX INVESTIGATION SUMMARY (2026-08-28)

What was checked
- Reviewed the code paths mentioned in your problem statement and compared them with current behavior/logs.
- Added a new API endpoint to run the same sample through all loaded models in one call.

Status of the reported issues
1) Raw PE feature extraction equivalence to training extractor
   - Partially improved, not fully solved.
   - Python built-in hash() instability is no longer used in import/export hashing.
   - However, uploaded PE extraction still uses a custom extractor path, so strict one-to-one equivalence with the original EMBER training extractor is still not guaranteed.

2) YARA StringMatch API mismatch
   - Fixed.
   - Current code handles both tuple-style and object-style match strings and includes a unit test for this path.

3) Entropy/packing conclusions from feature vectors
   - The old mean(hist)*8 bug is no longer present.
   - But feature-vector entropy and packing interpretations are still heuristic and should be treated as approximate, not ground-truth PE entropy.

4) MLP/TabNet "SHAP" labeling
   - Not fully fixed.
   - Tree models use TreeExplainer, but MLP/TabNet still use gradient/attention-style attributions (not true SHAP values), even though they are surfaced in SHAP-shaped output fields.

5) Correlated evidence overstatement
   - Partially improved.
   - Correlator now skips weak/zero indicators in some cases, but category-level matching can still overstate independence/corroboration in edge cases.

Why 7zip showed mostly benign but ember/tabnet showed malware
- This can happen from model-family differences and calibration differences across dataset groups (BODMAS-trained vs EMBER-trained variants).
- The Ember TabNet model can be more sensitive to feature regions that 7zip activates, while other models still stay on the benign side.
- Because raw uploaded PE vectorization is still not guaranteed to be identical to training-time extraction, cross-model disagreement on raw files is expected and should be interpreted cautiously.

New API added
- POST /api/predict/all
- Purpose: run one uploaded file or one feature vector across every loaded model and return per-model verdicts/confidence plus consensus vote.
- Useful for exactly the comparison workflow you described (same sample, all models).
